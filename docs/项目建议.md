## 一、调研结论：现在法律 AI 打到哪了

详见 [`research_2026.md`](research_2026.md)。压缩成五句话：

1. **产品端**：Harvey LAB（2026-05）用真实工作产物 + 专家 rubric + all-pass 评分，2026-10 的 LAB-AA v1.1 又加了幻觉检查。说明“像律师一样说”不够，**可核验**才是门槛。
2. **咨询端**：LeCoDe（ACL 2026）和 DLawBench（2026-06）已经把“多轮追问”做成 benchmark。GPT-4 级模型的关键事实追问召回只有 ~36%；DLawBench 最强模型 Resolution 0.562，还暴露“法律谄媚”。
3. **幻觉端**：LexAgentHallu（EMNLP 2026）把幻觉拆到轨迹级，发现“答案对、过程错”。
4. **时间端**：LegalSearch-R1（NLLP 2026）证明法律 agent 有训练截止时间偏置，且搜索 query 里几乎不带时间约束；时间一致性可以靠 RL 提升 57–80%。
5. **训练端**：RL 后训练集中在结构化推理（法条→罪名→量刑）与可验证奖励，不是“用 RL 灌法律知识”。

**对你的直接含义**：只做“法律搜索助手”在 2026 年已经过时；只做“咨询助手”也不再新。还能讲出差异的，是**事实被更正后的结论一致性**和**法条时间效力**——这两件事现有 benchmark 都没覆盖，而且正好是你的法律背景能定义清楚、CS 组员能实现的。

## 二、做搜索还是做咨询？proposal 要不要改？

### 结论

**改，但只改“表面”，不要推翻重来。**

- 把产品定位从 “legal research / search assistant” 改成 “legal consultation agent”。
- 把贡献从“多 agent 编排 + 缓存”收敛成三个机制：**要件事实门控、版本化案件记忆、机械核验**。
- 把“四个 specialist agent + LangGraph”删掉，改成单一状态机。四个 agent 在课程项目里通常是 prompt 换皮，增加失败面，不增加可测价值。
- LegalAgentBench 从“主评测”降为“可选外部检查”。它依赖远程 `law_api`，你的 RESEARCH_NOTES 已经记录了参数不匹配的问题；课程 demo 不该把命脉押在别人的服务上。

### 为什么咨询更好（但理由不是“咨询更高级”）

因为咨询**制造了 agent 必须做的决策**：现在够不够回答？先问哪个？问几次？什么时候必须停下来承认不知道？检索助手没有这些决策，评测只能测“检索到没有”，很难讲出 agent 的故事。

但要清醒：2026 年“咨询助手”本身已经被 LeCoDe / DLawBench 做掉了。所以你的卖点不能停在“我会追问”，而要停在：

> **当事人改口/补材料之后，我能不能只改该改的结论，并且不再引用旧结论。**

这句话是你和 80 个组拉开差距的地方。

### proposal 的最小改法

你现有的英文 proposal 结构很好，不用重写。按下面改：

| 位置 | 现在 | 建议 |
|---|---|---|
| 标题 | A Stateful Multi-Agent System for Evidence-Grounded Legal Research | Ask Before You Answer: A Sufficiency-Gated Legal Consultation Agent with Versioned Case Memory |
| §1 objective | research request → memorandum | consultation → sufficient facts → memorandum；加 RQ1/RQ2/RQ3 |
| §2 related work | DeepTutor + LegalAgentBench + J1 | 换成 DLawBench、LeCoDe、LexAgentHallu、LegalSearch-R1、Harvey LAB；DeepTutor 保留为记忆设计参考 |
| §3 control flow | 四个角色 + LangGraph | 单状态机 intake→gate→research→memo→verify→revise；说明为什么不用多 agent |
| §3 tools | 类案检索、结构化记录 | 删掉类案检索（没有真实裁判语料，容易造假）；换成法条版本检索 + 时效/补偿计算 + 文档读取 |
| §3 memory | 三层记忆 | 保留，但强调“事实级修订 + 依赖失效”，这是主贡献 |
| §4 evaluation | LegalAgentBench 30 题 × 4 配置 | 主实验改 12 个脚本案例 × 4 配置；LegalAgentBench 降为可选；加核验器注入测试、缓存重放、10 份人工盲审 |
| §5 计划 | 4 周 | 3 周即可，第一周必须用真实 API 重跑 |

| 条件 | 覆盖率 | 过早结论 | 引用核验 | 旧结论残留 |

- 版本化记忆把“改了事实但结论没改”从 100% 压到 0%。

### 课堂 5 分钟 demo 脚本

1. （30 秒）一句话：“法律咨询不是检索。客户说‘公司把我辞退了’，这句话不足以回答任何问题。”
2. 输入模糊问题 → agent 问两个问题，并显示“为什么问”（时效 / 公示）。
3. 回答 → 备忘录，**第一条争点是时效**，不是赔偿金额；引用表带生效期间。
4. 说“更正一下，我是 2022 年 8 月入职的” → 金额从 15 万变 12 万，旧事实划掉，缓存只失效 1 条。
5. 切到评测表：追问前后、修订前后、核验注入。
6. 最后一页：我们没测什么（通用法律能力、真实用户、类案）。

## 四、如果要把项目写进简历找算法实习

### 先改叙事

不要写“法律问答 RAG / 法律 chatbot”。写成：

> **Legal agent reliability：在事实不完整、会被更正的咨询场景下，如何让 agent 知道什么时候不该回答，并在事实修订后保持结论一致。**

这个叙事对两类岗位都成立：

- 法律 AI 公司（通义法睿、北大法宝、华宇、幂律、Harvey 类）：你有 domain + eval，稀缺。
- 通用 LLM/Agent 团队：你做过 state、tool、verification、eval，不是调包。

### 简历上放什么（按重要性）

1. **一个可复现的评测闭环**：12 案例 × 4 配置 × 指标定义 + 注入测试 + 人工盲审。写清楚“我定义了什么指标、为什么这个指标能区分好坏”。
2. **一个深机制**：事实级修订 + 依赖失效。写“更正后旧结论残留 100%→0%，只失效 1 条缓存”，比“使用了 LangGraph”有力得多。
3. **domain insight**：要件事实 schema、时效起止、法条版本。面试官会记住“这个人知道 2008 年前劳动仲裁是 60 日”。
4. **工程**：零依赖可跑、21 个单测、mock/API 双模式、trace 可视化。
5. **失败分析**：主动写“核验器抓不到论证错误”“脚本当事人太配合”。能讲失败的人，通常真的做过。

### 不要放什么

- “使用 LangChain/LangGraph 搭建多 agent 系统”（没有信息量）。
- “困惑度下降 X%”（和法律任务好坏没关系）。
- 任何没复现的数字（12%→91% 这种，面试官一问就穿）。
- “自研法律大模型”（你没训）。

### 三条可直接改写的 bullet

```
- 设计并实现法律咨询 agent 的「要件事实门控」：以 2 个案由的要件 schema 驱动追问，
  在 12 个受控案例上将关键事实覆盖率从 59% 提升到 100%，过早结论率从 58% 降到 0%。
- 实现事实级版本化记忆与依赖感知缓存：当事人更正事实后仅失效依赖该事实的 1 条缓存，
  重算时效与赔偿；旧结论残留率从 100%（复用旧分析）降到 0%，21 个单测覆盖时效/补偿/版本边界。
- 构建 claim-to-evidence 核验器（存在性/生效期/引文/金额/事实过期五类检查），
  在 55 次缺陷注入上全部检出、12 份干净分析零误报；并完成 10 份备忘录双人盲审。
```

### 面试会被问什么

- 为什么不用 end-to-end LLM 做全部？→ 因为引用和金额必须可核验；LLM 做抽取和解释，规则做可验证部分。
- 你的评测有没有偏？→ 有，金标准和规则同源；所以主结果是行为指标，不是法律正确率；人工盲审补。
- 如果当事人说谎？→ 当前把 user_stated 和 documentary 分开，冲突不覆盖；但没有测欺骗，是局限。
- 扩展到 100 个案由怎么办？→ schema 工程 + LLM 辅助生成 + 人工抽检；规则层按“可计算/可判定”优先。

## 五、怎么洗法律数据（如果以后做后训练）

先把话说死：**法律 RL 的数据核心不是“多”，是“可验证”**。自由文本的法律意见很难给奖励；法条 id、金额、期限、程序节点、要件是否满足，才是能机械核验的信号。

### 5.1 一条可复用的流水线

```
裁判文书 / 咨询对话
  → 去重、脱敏、按时间切分
  → 抽取三元组：法院认定事实 / 适用法条 / 裁判结果
  → 映射到要件 schema（每个案由一套）
  → 规则核验：金额、期限、法条版本、程序节点
  → 构造反事实：删掉一个要件事实 / 改一个日期 / 改一个主体
  → 得到 (输入, 可验证答案, 依据) 与偏好对
  → 人工抽检 5–10%，算 Kappa
```

### 5.2 具体建议

1. **先定 schema，再收数据**。没有要件 schema，收来的判决只是一堆文本；有了 schema，才知道缺哪个字段、哪个字段能构造负样本。
2. **优先收“可计算”的案子**：劳动补偿、工伤、民间借贷利息、交通事故赔偿、诉讼费。金额和期限能算，奖励就能自动给。
3. **反事实比正样本值钱**。同一个案子，把“已公示”改成“未公示”，结论从合法变违法；把解除日期从 2026-03 改成 2024-01，时效从没过变已过。这类样本能教会模型“哪个事实重要”，比堆 10 倍正样本有效。
4. **时间戳必须进数据**。每条法条带 `valid_from/valid_to`，每个案子带 `case_date`；训练/测试按时间切分，避免模型背到未来版本。这是法律数据最容易被忽略的泄漏。
5. **去重比清洗重要**。裁判文书有大量重复发布、系列案、模板化说理；按“当事人+案号+日期+事实哈希”去重，否则测试集会被训练集污染。
6. **不要把“法院认为”当金标准**。一审/二审/再审可能矛盾；优先用生效裁判 + 指导性案例 + 司法解释，冲突样本单独标“有争议”，别硬合成一个答案。
7. **脱敏与许可**：案号、姓名、身份证、地址、公司名都要处理；裁判文书网的抓取与使用要看清许可；教学 demo 用公开法条 + 自造案例最稳。
8. **奖励要防 hacking**：如果奖励只看“有没有引用”，模型会学会乱引；所以要有 existence / version / quote / number 四层检查，并且把“无据结论”单独扣分。
9. **标注一致性**：两个人标 100 条，算 Cohen's Kappa；低于 0.6 就先改标注手册，别急着扩量。
10. **小步验证**：先做 500 条可验证样本，跑 SFT/GRPO，看 `frac_reward_zero_std`；如果 >50%，先改奖励或输出格式，别加数据（你之前的经验已经证明这一点）。

### 5.3 你现在这个项目能怎么复用

- `data/elements.json` 就是最小号的要件 schema，可以直接扩成标注手册。
- `rules.py` 的时效/补偿/版本函数，可以直接当 reward 的 verifier。
- `eval/scripted_cases.json` 的“隐藏事实 + 更正”结构，可以扩成反事实数据生成器：每个案子生成 3–5 个“改一个要件”的变体。
- 这套东西的价值不在课程分数，而在于它证明你会**把法律问题变成可验证信号**——这正是法律 AI 后训练最缺的能力。

## 六、分数预期与优先级

目标 50–70 分，优先级从高到低：

1. **能跑、能演示、不崩**（最重要）。
2. **评测逻辑自洽**：指标定义清楚、有对照、承认局限。
3. **一个记得住的点**：更正后重算 / 时效先行 / 引用带版本。
4. 报告结构：动机 → 相关工作 → 方法 → 评测 → 结果 → 错误分析 → 局限。
5. 不要追求 SOTA、不要编数字、不要上多 agent。

做到 1–3，60 分稳；报告写清楚 4，冲 70。真正拉分的是“你知道自己没测什么”。
