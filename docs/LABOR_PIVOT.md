# 从“交通肇事答成劳动仲裁”到劳动争议问答助手

> 本文记录一次架构返工：为什么旧版会把交通事故答成劳动仲裁、怎么改、现在覆盖什么、还缺什么。
> 结论先行：旧版不是“模型笨”，是**路由写死 + 单一扁平问卷**；新版把“问什么”从固定清单改成
> **请求权 → 要件 → 事实/证据** 的动态遍历，并且**不再默认劳动**。

---

## 1. 复盘：为什么会把交通肇事答成劳动仲裁

旧版链路只有一句分类：

```python
ranked = schema.classify(text)
state.case_type = ranked[0][0] if ranked and ranked[0][1] > 0 else "labor_dismissal"
```

三个问题叠加：

1. **别名漏了“交通肇事”**：`tort_injury` 的别名只有“交通事故/车祸/撞伤/人身损害”等，
   “交通肇事”一个都不命中，分数为 0。
2. **0 分默认劳动**：分数为 0 时直接落到 `labor_dismissal`，于是问出解除日期、规章制度、
   工会——全是劳动仲裁的问题。
3. **一个案由一张扁平问卷**：即便分类对了，`elements.json` 里也只有两张固定表，
   问题顺序由 `priority` 写死；用户说“我是自己辞职的”也照样问规章制度和 2N。

所以这不是“再补几个关键词”能解决的。补关键词只能让这一个句子对，下一句“我被车撞了”
还会错；而且其他领域（离婚、借贷、合同）仍会被硬套劳动模板。

## 2. 新架构：先分诊，再按要件树追问

```
用户输入
  │
  ├─ 分诊 router：劳动 / 交通侵权 / 其他领域 / 不确定
  │     ├─ 其他领域 → 明确说“不覆盖”，不硬套
  │     ├─ 不确定   → 问“是哪类问题”，不默认劳动
  │     └─ 劳动     → 多标签识别请求权（可同时欠薪+加班+辞退）
  │
  ├─ 事实抽取（LLM 优先，规则兜底；只抽当前请求权声明的字段）
  │
  ├─ 要件树遍历 issues：
  │     请求权 claim → 要件 element → 要件事实 fact → 证据 proof
  │     element.requires 不满足 → 整个分支不问（如“自己辞职”不问工会/2N）
  │     只问当前分支上缺失的关键事实；同一问题最多问 2 次
  │
  ├─ 规则分析：每个请求权一个分析器 + 确定性计算器
  │
  ├─ 核验：引用存在/版本有效/引文对得上/金额=计算值/事实未过期
  │
  └─ 产出：备忘录 + 法律意见书 + 仲裁申请书 + 证据清单 + 期限卡片
```

### 2.1 分诊（`src/lexflow/router.py`）

- 劳动是**多标签**：一句话可以同时触发 `labor_wage` + `labor_overtime`。
- 交通肇事、撞人、追尾、交强险、事故认定书 → `tort_injury`。
- 离婚、借贷、房产、合同、刑事、消费、知识产权、行政 → `out_of_scope`，
  明确告诉用户“本版本不覆盖”，而不是用劳动模板回答。
- 只有“公司/老板/员工”这类弱信号 → `clarify`，列出劳动纠纷的 9 类问题让用户选，
  **不再默认辞退**。
- 会话上下文：用户回答“2026年3月15日”这种短句时，延续当前请求，不重新分诊。
- 明确切换（“不是劳动，是交通事故”）→ 重置请求与提问计数。

### 2.2 要件树（`src/lexflow/issues.py` + `data/elements.json`）

`data/elements.json` 由 `tools/build_elements.py` 生成，分两层：

- `facts`：90 个共享事实，每个事实只有一套问法；
- `claims`：13 个请求权，每个请求权把事实组织成 `elements`（要件），
  每个要件带 `requires` 条件、`why` 和 `proof`（证据）。

例如解除劳动合同：

| 要件 | 事实 | 条件 |
|---|---|---|
| 劳动关系成立 | 入职日期、用人单位、是否签合同 | 总是 |
| 解除行为与时间 | 解除日期、解除主体 | 总是 |
| 解除理由与程序合法性 | 解除理由、规章制度、违纪证据、工会…… | 严重违纪/不胜任/客观情况等分支 |
| 救济路径与金额 | 诉求、月工资、已付补偿 | 总是 |
| 仲裁时效与程序 | 是否已申请仲裁 | 核心事实具备后才问 |

条件示例：

```json
{"key": "training_or_transfer", "critical_if": [{"stated_reason": "不胜任工作"}]}
{"key": "union_notified", "critical_if": [{"who_initiated__in": ["单位单方解除", "被迫解除"]}]}
```

用户说“公司以严重违纪解除”，系统问规章制度公示、违纪证据；
用户说“不胜任”，系统问培训/调岗、代通知金；
用户说“我自己辞职”，系统不再问工会和 2N，改问是否属于第 38 条被迫解除。

### 2.3 问题不是写死的

`src/lexflow/questions.py` 做两件事：

1. **锚定上下文**：把已知事实带进问题。
   - “您提到公司以「严重违纪」为由解除——公司据以解除的员工手册有没有向您公示？”
   - “您说是「单位单方解除」——公司是哪一天通知您的？”
2. **LLM 改写（可选）**：只允许改写措辞，不允许新增事实/金额/日期/法条，不超过 80 字。
   mock 模式下走确定性模板，所以评测可复现。

问题排序也不是固定 `priority`：时间锚点（解除/受伤/欠薪期间）加权，
已回答过的问题降权，程序性时效问题在核心事实具备后加权。

### 2.4 多请求权合并

一次咨询可以同时跑：

- 辞退 + 欠薪；
- 欠薪 + 加班费；
- 工伤 + 交通事故（先工伤，提示侵权可另行主张、医疗费不重复受偿）。

备忘录按请求权分别给结论，共享同一张事实表；每个请求权的计算、时效、证据清单分开列。

## 3. 现在覆盖什么

| 请求权 | 典型问题 | 主要计算/判断 |
|---|---|---|
| `labor_dismissal` 解除/辞退 | 辞退、裁员、被迫解除、合同到期不续签 | N / N+1 / 2N、违法解除、时效 |
| `labor_wage` 工资/欠薪 | 拖欠工资、提成、年终奖、降薪 | 欠付金额、第 85 条加付赔偿 |
| `labor_overtime` 加班费 | 996、大小周、隐形加班 | 150%/200%/300%、特殊工时 |
| `labor_double_pay` 二倍工资 | 没签书面合同 | 最多 11 个月、解释二第 6/7 条 |
| `labor_work_injury` 工伤 | 工伤认定、伤残待遇 | 30 日/1 年、一次性伤残补助金 |
| `labor_social_insurance` 社保/公积金 | 断缴、补缴、被迫解除 | 补缴路径 vs 仲裁路径 |
| `labor_annual_leave` 年休假 | 未休年假 | 5/10/15 天、200% 额外 |
| `labor_noncompete` 竞业限制 | 补偿、违约金、解除 | 30%、2 年上限、3 个月未付 |
| `labor_maternity` 三期/生育 | 孕期被辞、产假工资 | 2N、生育津贴补差 |
| `labor_dispatch` 派遣/外包/新业态 | 骑手、主播、外包 | 从属性、责任主体 |
| `labor_contract` 合同/试用期 | 试用期、调岗降薪 | 试用期上限、书面变更 |
| `labor_procedure` 仲裁/诉讼程序 | 一裁终局、管辖、时效 | 45+15 日、15 日起诉 |
| `tort_injury` 交通事故 | 责任、伤残、保险 | 2022 城乡标准、三年时效 |

法条库从 15 部扩到 **26 部、1810 条**，新增：

- 劳动争议司法解释（二）（2025-09-01 施行）
- 工伤保险条例、社会保险法
- 职工带薪年休假条例
- 工资支付暂行规定
- 女职工劳动保护特别规定
- 劳动保障监察条例、工会法
- 保障农民工工资支付条例、失业保险条例、住房公积金管理条例

## 4. 知识库：法院/人社口径

`data/knowledge/practice_notes.json` 收录 16 条实务提示，每条带发布机关、日期、链接、
要点和地区差异提示。只做**摘要 + 自编清单**，不复制原文（人民法院报等有版权声明）。

| 来源 | 主题 | 关键点 |
|---|---|---|
| 《劳动合同法》/解释（一）（法条归纳） | 解除举证、制度公示、工会 | 单位对解除合法性负举证责任；制度需民主+公示；工会程序不能漏 |
| 最高法《劳动争议解释（二）》发布会 | 二倍工资、社保、竞业、时效抗辩 | 二倍工资按月算；放弃社保无效；时效抗辩逾期不提一般不支持 |
| 最高法劳动争议典型案例（2025） | 转包工伤、混同用工、竞业 | 转包工伤不以劳动关系为前提；混同用工可连带 |
| 人社部/最高法第四批典型案例 | 停工留薪、三期调岗、社保断缴 | 停工留薪延长要鉴定委员会确认；怀孕不能成为降薪理由 |
| 指导性案例 239 号 | 新业态劳动关系 | “支配性劳动管理”标准，合同名称不决定性质 |
| 人民法院报·三期关薪 | 生育津贴 | 津贴低于工资由单位补差 |
| 人民法院报·孕期教师 | 事实劳动关系 | 六年没合同仍可认定；违法解除 2N |
| 人民法院报·工伤 30 日 | 工伤认定 | 单位逾期申请，期间费用由单位承担 |
| 人民法院报·上海二中院加班调研 | 隐形加班 | 看指挥管理+实质劳动，不只看地点 |
| 人民法院报·空白合同 | 二倍工资 | 空白签字不等于订立书面合同 |
| 司法部 12348 | 一裁终局 | 只约束单位；劳动者仍有 15 日起诉权 |
| 中国就业网 | 未休年假 | 300% 中含正常工资，另主张 200%；按年度起算时效 |
| 北京人社局/门头沟政府 | 管辖/申请 | 履行地或单位所在地；可线上申请 |

这些提示会按当前请求权自动挂到备忘录的“实务提示”一节。

| 功能 | 入口 | 说明 |
|---|---|---|
| 法律意见书 | `/letter`、网页“文书” | 事实摘要、法律分析、结论、请求、风险、声明 |
| 劳动仲裁申请书 | `/arbitration` | 请求事项自动带金额、事实理由、证据清单、此致仲裁委 |

| 仲裁 vs 诉讼 | `/compare` | 前置、管辖、时效、审限、费用、一裁终局、执行、优缺点 |
| 打工人权益地图 | `/rights` | 入职前/在职/离职/维权四阶段 + 投诉渠道 |
| 关键期限卡片 | `/deadlines` | 仲裁时效、工伤 30 日/1 年、年假、竞业 |
| 合同条款体检 | `/contract <条款>` | 试用期、竞业、违约金、放弃社保、996、调岗降薪等 |
| 分析路径 | demo / 网页页签 / `/path` | 请求权基础 → 要件 → 事实，带状态与证据 |
| VOI 排序 | 自动 | 枚举假设回答，优先问“能改变结论”的事实 |
| 金额计算 | 自动 | N/N+1/2N、加班费、二倍工资、年假、竞业、工伤伤残 |

### 还可以做（按价值排序）

1. **期限提醒**：把仲裁时效、15 日起诉、工伤 30 日做成可订阅提醒（需要调度器）。
2. **Offer/合同 PDF 上传与 OCR**：现在只能粘贴文本；接入 PDF 解析后可直接体检。
3. **证据保险箱**：截图/录音上传，计算哈希、记录时间戳，生成证据目录。
4. **谈判脚本**：N/N+1/2N 三档报价、BATNA、话术；离职谈判是高频场景。
5. **庭审/仲裁预演**：模拟单位抗辩（自愿加班、已支付、严重违纪），给出应对。
6. **城市参数库**：当地最低工资、社平工资 3 倍封顶、工伤一次性医疗/就业补助金。
7. **类案检索**：接入公开裁判文书（注意许可与脱敏），按争点找类案。
8. **多语言/语音**：面向农民工、外卖骑手的语音输入和方言/多语言。
9. **执行阶段**：裁决后对方不履行 → 强制执行、先予执行。
10. **人工律师复核**：高风险结论转人工，形成“AI 初筛 + 律师签字”的交付。

## 7. 评测：中国有没有专门的劳动争议评测集？

有，但**专门 + 多轮咨询**这两个条件同时满足的很少。

### 7.1 LabourLawBench（最直接的中文劳动法基准）

- 论文：*Chinese Labor Law Large Language Model Benchmark*，Lan et al.，arXiv:2601.09972（2026-01）。
- 数据：[IEEE DataPort, DOI 10.21227/jc8k-yt12](https://ieee-dataport.org/documents/labor-law-bench)，CC BY 4.0，下载需登录（免费账号）。
- 规模：**12 个任务（T1–T12）× 12 类案由（C1–C12）**；T1 法条背诵 3165 条，T2 单选 177，
  T3 多选 88，T4–T9 每类 50（共 600/任务），T10 670，T11–T12 各 384。
- 任务：法条背诵、知识问答、案由预测、待遇/赔偿项目预测、NER、诉请挖掘、争议焦点、
  法条预测（事实/场景）、案例分析（给/不给法条）。
- 案由：人事争议、养老、医疗、失业、工伤、生育保险待遇、劳务派遣、确认劳动关系、
  福利待遇、竞业限制、经济补偿、追索劳动报酬。
- 指标：ROUGE-L、accuracy、F1、soft-F1，另加 GPT-4 主观评分。
- 来源：江苏近五年公开裁判文书“查明事实/理由”+ 国家考试题 + 法条。
- **局限**：以**单轮**任务为主，不测“该不该先问、问得对不对、当事人更正后是否重算”；
  也不测备忘录/文书。

### 7.2 CLC-UKET（老师 Huiyuan Xie 的英国数据集）

- 论文：[The CLC-UKET Dataset](https://aclanthology.org/2024.nllp-1.7/)，Xie, Steffek et al.，NLLP 2024。
- 规模：约 **19,090** 个 UK Employment Tribunal 案件，其中 **14,582** 个用于结果预测；
  标注事实、请求、法条、判例、结果、理由、管辖。
- 任务：多分类结果预测；有真人预测基线。
- 局限：英国法、英文、结果预测，不是中国法/多轮咨询；但**方法学**（LLM 自动标注 + 人工校验、
  按案由分层、human baseline）值得借鉴。

### 7.3 相邻评测

| 评测 | 规模/任务 | 与劳动争议的关系 | 可用性 |
|---|---|---|---|
| [DLawBench](https://github.com/SKYLENAGE-AI/DLawBench) | 461（公开 60）中/美案件，4 种当事人人格，7 指标 | 最接近“咨询对话”，但非劳动专用；中文子集需按案由筛选 | 公开 |
| [LeCoDe](https://github.com/PiLab-ZJU/LeCoDe) | 3,696 段真实咨询、5 轮、12 指标 | 最接近多轮追问；非劳动专用 | 需申请 |
| [LexRAG](https://github.com/CSHaitao/LexRAG) | 1,013 文档 × 5 轮、17,228 法条 | 测检索，不测咨询 | 公开 |
| [LawBench](https://github.com/open-compass/LawBench) | 20 任务、知识/理解/应用 | 通用法律，非劳动专用 | 公开 |
| CAIL 系列 | 刑事为主 | 劳动不是独立赛道 | 公开 |

### 7.4 结论与建议

**结论**：中国有专门的劳动法基准（LabourLawBench），但没有公开的、
专门面向**劳动争议多轮咨询**（追问→要件→备忘录）的评测集。LeCoDe 有多轮但非劳动专用且需申请；
DLawBench 有当事人人格但非劳动专用。**这是一个可以理直气壮写的 gap。**

**建议的三层评测**：

1. **法律知识层**：LabourLawBench 的 T4（案由）、T5（待遇项目）、T7（诉请）、T8（争议焦点）、
   T9/T10（法条预测）、T11/T12（案例分析）。注意它是单轮，不能拿来证明“追问能力”。
2. **多轮咨询层**：LeCoDe（若能申请）过滤劳动子集，测追问召回；或 DLawBench 中文子集。
3. **自建层（最值得做）**：30–50 个劳动争议场景，覆盖 12 类请求权，每个场景带
   - 隐藏事实表（当事人知道但不会主动说）；
   - 金标准要件（哪些事实必须问）；
   - 金标准结论/金额/时效；
   - 1 次事实更正；
   - 指标：要件覆盖率、追问召回、过早结论率、金额/时效准确率、引用可核验率、更正后旧结论残留。

   仓库里的 `eval/protocol.py` 已经支持隐藏事实、脚本化当事人和更正注入，
   把 `data/eval/scripted_cases.json` 从 12 个扩到 30–50 个、覆盖新请求权即可。
   **这比在公开榜单上刷一分更有信息量。**

   而且这件事**可以主要交给 AI**：生成器造题 → 符号规则层当 oracle 判卷 →
   另一个模型审题 → 人工只抽查 10–20%。流水线、验收标准和风险见
   [`docs/TODO_AI_BENCH.md`](TODO_AI_BENCH.md)。

## 9. 边界

1. 法条是真实公开文本，但**金额计算有简化**：未接入当地社平工资 3 倍封顶、
   工伤地方补助金、医疗票据、伤残系数。
2. 规则层是作者编码的，**保证一致性不等于保证法律论证正确**；高风险结论仍需律师复核。
3. 知识库是摘要，**不是裁判文书全文**；地区差异用 `caveat` 标注，具体以当地口径为准。
4. 评测主表仍是内部脚本（mock），数字只说明管线一致性和追问行为，
   **不说明法律能力**；LabourLawBench/LeCoDe 是下一步外部效度。
5. 不提供“胜诉率预测”；没有真实类案检索，不虚构案号或裁判结果。
