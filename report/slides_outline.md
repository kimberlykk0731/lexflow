# 8 页幻灯片大纲（5 分钟）

> 原则：每页一个观点、一张图、不超过 3 行字。答辩时把“我们没测什么”放在最后，比多吹一句更加分。

## 1. 标题

**LexFlow：先问再答的法律咨询 Agent**

- 一句话：大多数法律 RAG 回答“问题”，我们先判断“这个问题现在能不能回答”。
- 副标题：要件事实门控 + 法条版本 + 事实修订后的重算
- 底部：课程名 / 组号 / 日期

讲稿：我们不打算做一个更大的法律模型，只做一个更诚实的咨询流程。

## 2. 问题：咨询不是检索

左边：客户原话“公司把我辞退了”。
右边：三种结论——

- 未公示规章制度 → 违法解除，2N
- 已公示 + 有证据 + 通知工会 → 合法解除，0
- 解除超过一年 → 时效抗辩

底部一行：**同一个问题，缺三个事实，结论完全不同。**

讲稿：检索助手会把第一句话直接变成答案；咨询助手要先知道缺什么。

## 3. 2026 年别人做到哪了

- LeCoDe（ACL 2026）：3,696 段真实咨询，强模型只问到 ~36% 关键事实。
- DLawBench（2026）：461 个案件、四种当事人人格，最强模型 0.562。
- Harvey LAB-AA（2026-10）：真实工作产物 + rubric + 幻觉检查。

右下角一句：**“咨询”已经被 benchmark 化了，所以我们不把它当卖点。**

## 4. 方法：一个状态机，不是四个 agent

放架构图（`report/figures/architecture.png`）。

- 流程：intake → 够不够？→ 检索/规则 → 备忘录 → 核验 → 修订
- 模型只做抽取和白话解释；引用、金额、期限由规则层算。
- 事实带来源、修订号、被取代链；改一个事实只失效依赖它的缓存。

讲稿：四个 specialist agent 在课程项目里通常是 prompt 换皮，我们用一个显式状态机，换来可复现。

## 5. 三个机制

| 机制 | 一句话 | 指标 |
|---|---|---|
| 要件事实门控 | 缺关键事实就追问，不硬答 | 覆盖率、过早结论率 |
| 时间效力 | 检索和引用都限定在案发日有效的版本 | 版本/时效一致率 |
| 版本化记忆 | 更正后只重算受影响的部分 | 旧结论残留率 |

举一个时间效力的例子：2022-05-01 前残疾赔偿金区分城乡，之后统一按城镇标准；同一起事故，日期不同，适用解释不同。

## 6. 评测：12 个案例 × 4 配置

放主表（只保留四行四列：覆盖率、过早结论、引用核验、旧结论残留）。

- `answer_first` / `gate_only` / `full` / `full_no_revision`
- 12 案例（7 劳动 + 5 侵权），隐藏事实 + 更正脚本
- 真实 API 跑完 4 个条件约 0.17 元

讲稿：金标准是手算的，规则层也是我们写的，所以“违法/金额 100%”只能说明管线一致；真正有信息量的是行为差异。

## 7. 结果：三个数字 + 一个 bug

- 覆盖率 57.5% → 100%
- 过早结论 58.3% → 0%
- 旧结论残留 100% → 0%（`full_no_revision` → `full`）

右下角“错误分析”：

- API 第一轮跑出 L06 时效错：客户说“2024年1月”，模型归一成 2024-01-01，门控当成精确日。
- 修复：从原文恢复“月精度”，再追问具体哪一天。
- 这说明：危险的不是错一句话，是一个错状态被后面当成确定事实。

## 8. 局限与结论

- 只有两个案由、12 个案例、脚本化当事人；不外推为通用法律能力。
- 时效起算、社平工资封顶、损害赔偿金额都做了简化。
- 核验器抓不到“法条选错但版本有效”“论证跳跃”。
- 下一步：第三个案由、四种当事人人格、10 份人工盲审、embedding 检索对照。

最后一句话：**我们没有让模型更懂法，我们让 agent 更清楚自己什么时候不该回答。**
