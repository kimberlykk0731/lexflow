# 5 分钟演示脚本

## 演示前 10 分钟

- [ ] `.env` 里有 DeepSeek key；`cd lexflow && LEXFLOW_LLM=api make ui`
- [ ] 打开 `http://localhost:8502`，点一次“载入示例对话”预热（之后点“新会话”）
- [ ] 浏览器缩放 110%，关掉无关标签页
- [ ] 备用 1：`runs/labor_demo_report.md`（完整 6 轮文字记录）
- [ ] 备用 2：提前录好的 90 秒屏
- [ ] 如果 API 挂了：`LEXFLOW_LLM=mock make ui`，开场说明“这是离线兜底，流程一样，只是不调模型”

---

## 0:00–0:30　开场

> “法律咨询不是检索。客户说‘公司把我辞退了’，这句话其实回答不了任何问题：有没有公示制度、有没有通知工会、解除多久了，每一个都能让结论从 2N 变成 0，或者变成‘时效已过’。我们做的是一个先判断‘现在能不能回答’的 agent。”

## 0:30–1:30　模糊提问 → 追问

点“新会话”，输入：

```
公司把我辞退了，理由是严重违纪，我想问能赔多少钱
```

指着右侧追问：

> “它没有直接算钱，先问了解除日期和公示情况。每个问题下面写了‘为什么问’——解除日期决定时效，公示决定制度能不能作为依据。”

如果它多问/少问，不要慌，按顺序补：

```
2026年3月15日通知的，员工手册从来没给我看过，也没签收
```

## 1:30–2:30　事实齐备 → 备忘录

输入：

```
公司有员工手册，但制定没经过民主程序，也没通知工会。我2021年5月入职，月薪一万五，想要赔偿金。
```

指着备忘录：

> “第一条争点不是赔偿金额，是时效——律师先看能不能打。然后是公示、举证责任、工会程序。事实表里每一条都标了来源和版本；引用表里每条法条都带生效期间。”

如果它还在追问违纪证据，补一句：

```
违纪的事公司只有口头说，没有书面证据
```

## 2:30–3:30　更正事实 → 重算

输入：

```
更正一下，我是2022年8月1日入职的，不是2021年5月。
```

指着金额和事实表：

> “金额从 15 万变成 12 万，旧值被划掉，但解除日期、公示、工会这些没变的事实没有重问。缓存只失效了依赖入职日期的那一条。”

## 3:30–4:30　评测

切到幻灯片主表：

- 覆盖率 57.5% → 100%
- 过早结论 58.3% → 0%
- 旧结论残留 100% → 0%（`full_no_revision` → `full`）
- 12 案例 × 4 配置，真实 API 跑完约 0.17 元

> “金标准是我们手算的，规则层也是我们写的，所以‘违法/金额 100%’只能说明管线一致；真正有信息量的是行为差异。核验器另外用 55 次缺陷注入测，5 类全检出、干净分析 0 误报。”

## 4:30–5:00　局限与收尾

> “只有两个案由、12 个案例、脚本化当事人，不能外推成通用法律能力。时效起算、社平工资封顶、损害赔偿金额都做了简化。我们没让模型更懂法，我们让 agent 更清楚自己什么时候不该回答。”

## 可能被问的问题

**Q：案例是真实的吗？**
A：不是真实判决，是合成案例；法条原文是真的，金标准是按法条手算的。报告里明确写了。

**Q：评测是不是自己出题自己考？**
A：金标准和规则层同源，所以法律结论的一致性不作为能力宣称；主结果是行为指标（覆盖率、过早结论、旧结论残留），并配 10 份人工盲审。

**Q：为什么不用 DLawBench / LeCoDe？**
A：DLawBench 是通用咨询策略，我们的 schema 只覆盖两个案由，直接跑会大面积分错类；LeCoDe 数据要签协议。它们作为相关工作与外部效度讨论，不作为成绩来源。

**Q：和普通 RAG 有什么区别？**
A：RAG 是“检索→生成”；我们是“状态→门控→检索→规则→核验→修订”。核心差别是事实有版本，结论能只改该改的部分。

**Q：扩展性？**
A：加案由就是加一份要件 schema 和一组规则；可计算/可判定的优先，纯裁量的（比如“严重”的程度）留给人工。

**Q：为什么不用多 agent？**
A：课程项目里多 agent 通常是 prompt 换皮，增加失败面；显式状态机更容易复现和消融。
